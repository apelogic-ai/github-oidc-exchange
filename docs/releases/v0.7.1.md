# github-oidc-exchange v0.7.1

> Historical release evidence. Current behavior and compatibility are defined
> by the [installation guide](../installation.md),
> [consumer contracts](../consumer-contract-v1.md), and
> [0.7.2 upgrade guide](../upgrade-v0.7.2.md).

## Summary

Version 0.7.1 hardens signing-key lifecycle and Kubernetes network policy
without changing either GitHub policy/token contract. Runtime signing now
enforces the active ES256 and optional RSA key validity window. Public and
workload readiness fail before expiry using a configurable threshold, and
seconds-to-expiry gauges support earlier alerting.

`keyring-tool` accepts bounded key lifetimes and adds `export-jwks`, which
detects ES256 or RSA keyrings and emits a public-only JWKS document. The
rotation runbook requires overlapping keys to reach every mounted/static
verifier before Identity activates the new signer. Identity does not call or
restart downstream verifiers; the signed JWKS handoff remains the integration
boundary.

The chart now requires Kubernetes 1.32 or newer. Enabling ServiceMonitor also
requires nonempty metrics namespace and Pod selectors because metrics share
port 8080 with the public exchange handler. The packaged production values
shape remains version-neutral and rejects image placeholders until immutable
coordinates are supplied from a verified release handoff.

## Compatibility and activation

| Application/chart | Policy | Output | Activation |
| --- | --- | --- | --- |
| 0.7.1 / 0.7.1 | v5 | `steward-task-v2` | Default; continues to issue the unchanged token contract |
| 0.7.1 / 0.7.1 | v6 | `steward-task-v3` | Explicit values plus separate policy object |
| 0.7.0 / 0.7.0 | v5 or v6 | v2 or v3 | Historical rollback pair; lacks 0.7.1 key-expiry enforcement and static-JWKS tooling |

Policy `github-oidc-exchange.apelogic.io/v5` remains the chart default. Policy
`github-oidc-exchange.apelogic.io/v6` remains an explicit opt-in. The issuer,
RFC 8414/OpenID discovery routes, exchange routes, audiences, token claims,
and two-minute token lifetime are unchanged. Discovery continues to advertise
the exact `github_oidc_audience` required for GitHub assertions.

Follow the [0.7.1 upgrade guide](../upgrade-v0.7.1.md). Verify Kubernetes 1.32,
supply both monitoring selectors when ServiceMonitor is enabled, inspect key
expiry before rollout, and preserve the selected policy object. A normal
rollback restores the complete prior application/chart revision and policy
reference; it does not undo an independently completed key rotation.

## Release evidence

The release workflow creates `release-manifest.json` containing immutable
image/chart coordinates, source commit, workflow run, native amd64 and arm64 container
platform digests, default `policy_contract`/`identity_contract`, and
`supported_policy_contracts`/`supported_identity_contracts`. The release also
carries SPDX SBOM and SLSA provenance attestations.

Verify the signed handoff and artifacts with `cosign verify-blob`,
`cosign verify`, and `cosign verify-attestation`. The ECR workflow records
`ecr_image` and `ecr_chart`; the portable workflow requires no AWS account.
Tag-only production deployment is unsupported. `image.digest` must come from
the release handoff or a verified manifest-preserving mirror; all-zero and
homogeneous placeholder digests are rejected.
