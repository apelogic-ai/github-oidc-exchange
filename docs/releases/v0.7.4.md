# github-oidc-exchange v0.7.4

## Summary

Version 0.7.4 is a patch release for release-boundary hardening, actionable
startup diagnostics, reproducible native builds, and Kubernetes DNS
compatibility. Identity's public routes, audiences, policy schemas, two-minute
token lifetime, and default `steward-task-v2` behavior are unchanged.

Release workflows now publish intermediate image and chart manifests by digest
without public `candidate-*` tags. An existing immutable version is rejected in
preflight before architecture builds begin. The public-release boundary scans
every workflow file case-insensitively for private-registry integrations and
uses an explicit host allowlist for release evidence. Contract scripts require
Bash 5+ and report a missing workflow anchor by name.

GitHub JWKS failures now preserve the failing stage and underlying transport,
HTTP-status, decode, or key-validation cause. Startup logs identify the failed
component, and an exchange that cannot refresh signing keys returns the
existing `temporarily_unavailable` response while recording an
`exchange_failed` event instead of treating the dependency failure as an
invalid assertion.

The installation guide lists the native C compiler required by Rust's crypto
dependencies and provides a single-architecture container build that does not
require CPU emulation. The chart admits reply traffic only from its configured
DNS peers, covering CNIs that do not retain DNS reply state; the Kubernetes
1.36 regression now reaches the API server through its Service DNS name.

## Release evidence

`release-manifest.json` contains the source commit, workflow run, immutable
public image and chart coordinates, native amd64 and arm64 platform digests,
and supported contract identifiers. The release workflows publish directly to
GHCR; `public_distribution.direct_publish` replaces the historical
`manifest_preserving_mirror` field.

The release attaches the packaged chart, contract schemas/examples, platform
descriptors, public signature bundles, `release.slsa.json`, and the signed
release manifest. `release.slsa.json` is the human-inspectable SLSA predicate,
not a standalone signed statement. Treat it as authoritative only after
`cosign verify-attestation --type slsaprovenance1` binds it to the exact signed
OCI digest. Verify the handoff with `cosign verify-blob`, and verify OCI
signatures, SPDX SBOM attestations, and SLSA provenance attestations with
`cosign verify` and `cosign verify-attestation`.
