# github-oidc-exchange v0.7.5

## Summary

Version 0.7.5 is a non-breaking policy, operations, and release-safety update.
It adds explicit owner-wide admission to policy v6, reusable-workflow
selectors (`job_workflow_refs` and `job_workflow_shas`), actionable dependency readiness, and a versioned observability
contract. Policy v5 remains the chart default. No new value is required, and
public OCI coordinates, signer identity, and release signature filenames are
unchanged.

Policy v6 can now set `repository_id` to `"*"` for one positive canonical
numeric `owner_id`. Every configured subject, event, ref, reusable-workflow
ref, and reusable-workflow SHA selector still applies. Exact repository rules
remain the default, cannot overlap an owner-wide rule for the same owner, and
the issued source provenance always contains the concrete signed repository
ID.

The pairing guide now covers OpenShell's one-hour JWKS cache, the required
restart after enabling the workload exchange, and short-lived operator CLI
authentication through a dedicated ServiceAccount policy entry. GitHub policy
guidance shows both classic and immutable-ID subject forms and how to inspect
the live subject customization.

Readiness now checks the bounded age of the cached GitHub JWKS and cached,
one-second sentinel access to the Kubernetes Lease API in addition to enabled
signing keys. It returns stable failed-check names such as `github_jwks` and
`replay_ledger` in a bounded JSON response. Cached GitHub keys survive a
transient refresh failure for a configurable six-hour default, with
single-flight/rate-limited refreshes and the
`github_oidc_exchange_jwks_age_seconds` and
`github_oidc_exchange_jwks_refresh_failures_total` metrics.
Every Prometheus metric has HELP/TYPE metadata and the GitHub exchange exposes
a latency histogram. The established audit events and reason values are
documented unchanged in the operator observability contract.

The release workflow runs the public-boundary guard in preflight, shares one
release-evidence generator with CI, and covers bracket variables,
command-substituted/reordered CLI invocations, and bare-host evidence.

## Compatibility and activation

| Application/chart | Policy | Output | Activation |
| --- | --- | --- | --- |
| 0.7.5 / 0.7.5 | `github-oidc-exchange.apelogic.io/v5` | `steward-task-v2` | Default; unchanged behavior |
| 0.7.5 / 0.7.5 | `github-oidc-exchange.apelogic.io/v6` | `steward-task-v3` | Explicit policy selection |
| 0.7.4 / 0.7.4 | v5 or v6 | matching v2 or v3 | Supported rollback pair |

Follow the [0.7.5 upgrade guide](../upgrade-v0.7.5.md). Owner-wide admission
is opt-in policy content and is not introduced by upgrading the binary/chart.

## Release evidence

Verify `release-manifest.json` and its unchanged
`release-manifest.sigstore.json` bundle, then verify the exact image and chart
digests plus their signatures and SPDX/SLSA attestations. The release retains
`public-image-signature.sigstore.json` and
`public-chart-signature.sigstore.json`.
