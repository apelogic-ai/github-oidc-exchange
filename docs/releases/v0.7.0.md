## Summary

Version 0.7.0 exposes RFC 8414 authorization-server metadata at
`/.well-known/oauth-authorization-server` for steward-run and retains
`/.well-known/openid-configuration`. Both routes return the same issuer,
`jwks_uri`, exchange endpoint, exact `github_oidc_audience`,
`supported_policy_contracts` through `policy_versions_supported`, and
`supported_identity_contracts` through `identity_contracts_supported`.

The issuer is now explicitly an HTTPS origin only. Runtime and Helm validation
reject path-, query-, and fragment-bearing values so the advertised
`/jwks.json` and `/v1/exchange` URLs always correspond to routes exposed by
the application, Ingress, and HTTPRoute.

Policy `github-oidc-exchange.apelogic.io/v5` remains the chart default and
continues to issue the unchanged `steward-task-v2` contract. Policy
`github-oidc-exchange.apelogic.io/v6` remains an explicit opt-in and issues
`steward-task-v3`. Identity does not decide absent optional source selectors;
Steward performs any user binding and retains Task authority.

## Compatibility and activation

| Application/chart | Policy | Output | Activation |
| --- | --- | --- | --- |
| 0.7.0 / 0.7.0 | v5 | `steward-task-v2` | Default, behavior-preserving |
| 0.7.0 / 0.7.0 | v6 | `steward-task-v3` | Explicit values plus separate policy object |
| 0.6.0 / 0.6.0 | v5 or v6 | v2 or v3 | Historical rollback pair; OpenID discovery only |

Follow the [0.7.0 upgrade guide](../upgrade-v0.7.0.md). Preserve the selected
policy object during a behavior-preserving upgrade. Never rewrite or delete
the v5 ConfigMap during v6 activation; use a separately named v6 object and
an atomic rollback of application/chart plus policy reference.

## Release evidence

The release workflow creates `release-manifest.json` containing immutable
image/chart coordinates, source commit, workflow run, native amd64 and arm64 container
platform digests, default `policy_contract`/`identity_contract`, and
`supported_policy_contracts`/`supported_identity_contracts`. The release also
carries SPDX SBOM and SLSA provenance attestations.

Verify the signed handoff and artifacts with `cosign verify-blob`,
`cosign verify`, and `cosign verify-attestation`. The ECR workflow records
`ecr_image` and `ecr_chart`; the portable workflow requires no AWS account.
Tag-only production deployment is unsupported. `image.digest` must come from
the release handoff or a verified manifest-preserving mirror; all-zero and
homogeneous placeholder digests are rejected.
