# github-oidc-exchange v0.6.0

## Summary

Version 0.6.0 adds opt-in policy
`github-oidc-exchange.apelogic.io/v6` and output contract
`steward-task-v3`. The chart default remains
`github-oidc-exchange.apelogic.io/v5`, which continues to issue the unchanged
`steward-task-v2` contract.

Policy v6 keeps signed numeric repository owner/repository IDs as the trust
boundary. Subjects, events, and refs are optional exact compatibility
selectors. Actors, allowed email domains, and acting-group prefix form an
optional all-or-none compatibility bundle. Present selectors are validated
and enforced; absent selectors do not make Identity decide which
actors, branches, tags, pull requests, workflow subjects, or events may submit
from the admitted repository. Signed provenance is still shape- and
consistency-validated and preserved.

The v3 subject is `github-actions:actor:<positive canonical numeric actor ID>`.
The required bounded signed login is emitted as `actor_login` display
metadata. Without the actor compatibility bundle, `email`, `email_verified`,
and `groups` are all absent. With it, Identity emits the complete validated
v2-compatible set. Steward owns user binding and Task authorization. The
release includes a checked-in v3 consumer conformance fixture.

Discovery now publishes `github_oidc_exchange_endpoint`, exact input
`github_oidc_audience`, `policy_versions_supported`, and
`identity_contracts_supported`.

Follow the [0.6.0 upgrade guide](../upgrade-v0.6.0.md). Never rewrite or delete
the v5 ConfigMap during v6 activation. After activation, rollback switches the
application/chart revision and policy reference back together.

## Release evidence

The release workflow creates `release-manifest.json` containing immutable
image/chart coordinates, source commit, workflow run, native amd64 and arm64 container
platform digests, default `policy_contract`/`identity_contract`, and
`supported_policy_contracts`/`supported_identity_contracts`. The release also
carries SPDX SBOM and SLSA provenance attestations.

Verify the signed handoff and artifacts with `cosign verify-blob`,
`cosign verify`, and `cosign verify-attestation`. The optional ECR workflow
records `ecr_image` and `ecr_chart`; the portable workflow requires no AWS
account. Tag-only production deployment is unsupported. `image.digest` must
come from the release handoff or a verified manifest-preserving mirror;
all-zero and homogeneous placeholder digests are rejected.
