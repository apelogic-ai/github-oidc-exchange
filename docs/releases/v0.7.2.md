# github-oidc-exchange v0.7.2

## Summary

Version 0.7.2 is a patch release that tightens the public release boundary and
brings operator integration guidance in line with the current steward-run
discovery contract. It does not change Identity's runtime routes, token
claims, audiences, policy schemas, or two-minute token lifetime.

The release workflow continues to scan private build candidates internally,
but public GitHub release assets no longer contain private-registry
descriptors, raw registry scan reports, or raw SBOM inputs. Public GHCR image
and chart references receive signed SPDX SBOM and SLSA provenance
attestations generated from the public references. The chart configuration's
Kubernetes compatibility range is derived directly from `Chart.yaml`.

The documentation now records steward-run's default discovery chain from the
Steward API through RFC 9728 protected-resource metadata to Identity RFC 8414
metadata. It also defines the exact Steward controller ServiceAccount,
workload audience, Identity policy, TLS, OpenShell audience, and role pairing.
Identity remains independently deployable and does not call Steward.

## Compatibility and activation

| Application/chart | Policy | Output | Activation |
| --- | --- | --- | --- |
| 0.7.2 / 0.7.2 | v5 | `steward-task-v2` | Default; continues to issue the unchanged token contract |
| 0.7.2 / 0.7.2 | v6 | `steward-task-v3` | Explicit values plus separate policy object |
| 0.7.1 / 0.7.1 | v5 or v6 | v2 or v3 | Historical rollback pair; same runtime token contracts |

Policy `github-oidc-exchange.apelogic.io/v5` remains the chart default. Policy
`github-oidc-exchange.apelogic.io/v6` remains an explicit opt-in. Discovery
continues to advertise the exact `github_oidc_audience` required for GitHub
assertions, plus `policy_versions_supported` and
`identity_contracts_supported`.

Follow the [0.7.2 upgrade guide](../upgrade-v0.7.2.md). Preserve the complete
application/chart and policy pairing during activation and rollback.

## Release evidence

`release-manifest.json` contains the source commit, workflow run, immutable
public image and chart coordinates, native amd64 and arm64 container platform
digests, and supported contract identifiers. It contains no `ecr_*` fields or
private-registry coordinates. The signed manifest bundle, packaged chart,
platform descriptors, and public OCI signature bundles remain downloadable
release assets.

Verify the handoff with `cosign verify-blob`. Verify public OCI signatures and
the SPDX SBOM and SLSA provenance attestations with `cosign verify` and
`cosign verify-attestation`. `image.digest` must come from the verified
release handoff or a verified manifest-preserving mirror; tag-only production
deployment is unsupported.
