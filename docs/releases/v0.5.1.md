# github-oidc-exchange v0.5.1

> Historical release evidence. Current behavior and compatibility are defined
> by the [installation guide](../installation.md) and
> [consumer contracts](../consumer-contract-v1.md).

This release hardens Helm image-reference validation. The chart now rejects
the all-zero `image.digest` and every homogeneous hexadecimal sentinel before
rendering a Kubernetes object. A chart-owned preflight reports the exact
values path and requires an immutable digest from a published release handoff
or a verified manifest-preserving mirror. Tag-only production deployment
remains unsupported.

Normal identity behavior is unchanged. GitHub policy remains
`github-oidc-exchange.apelogic.io/v5`; successful exchanges retain the fixed
`steward-task-api` audience, `steward-task-v2` identity contract, two-minute
lifetime, source provenance, replay protection, signing, workload exchange,
and browser HOP-1 contracts.

## Required migration

1. Download and verify this release's signed `release-manifest.json`.
2. Set `image.repository`, optional `image.tag`, and `image.digest` together
   from its immutable image reference. If mirroring, copy by source digest and
   record the verified destination descriptor.
3. Run `bash scripts/validate-chart-values.sh VALUES_FILE` and strict Helm lint
   before installation or reconciliation.
4. Deploy application/chart 0.5.1 together. Retain the existing policy v5
   ConfigMap, keyring, and rollout revisions unless those inputs independently
   changed.

Existing values containing an all-zero or homogeneous sentinel digest are now
invalid. Static validation intentionally does not test registry reachability.
See the complete
[upgrade guide](https://github.com/apelogic-ai/github-oidc-exchange/blob/v0.5.1/docs/upgrade-v0.5.1.md).
Rollback restores the complete 0.5.0 application/chart plus policy v5 pair and
its previously verified immutable image digest; a sentinel or tag-only rollback
is not supported.

## Release evidence

The release workflow runs Rust formatting, linting, tests, policy/schema and
documentation drift checks, Helm validation, native amd64 and arm64 container
smokes, chart and image vulnerability scans, public exact-digest pull checks,
and signature, SPDX SBOM, and SLSA provenance verification. Exact public GHCR
and private ECR image/chart coordinates, per-platform image digests, source
commit, policy contract, and identity contract are in the signed
`release-manifest.json` attached to this release.

Download and verify the handoff with GitHub CLI, `jq`, `oras`, and Cosign 3.1.2
or newer:

```sh
export RELEASE_REPOSITORY=apelogic-ai/github-oidc-exchange
export RELEASE_VERSION=v0.5.1
export RELEASE_IDENTITY=https://github.com/apelogic-ai/github-oidc-exchange/.github/workflows/release.yml@refs/heads/main
export RELEASE_OIDC_ISSUER=https://token.actions.githubusercontent.com
export RELEASE_EVIDENCE_DIR="$(mktemp -d)"
gh release download "$RELEASE_VERSION" --repo "$RELEASE_REPOSITORY" \
  --dir "$RELEASE_EVIDENCE_DIR"
cd "$RELEASE_EVIDENCE_DIR"

cosign verify-blob \
  --bundle release-manifest.sigstore.json \
  --certificate-identity "$RELEASE_IDENTITY" \
  --certificate-oidc-issuer "$RELEASE_OIDC_ISSUER" \
  release-manifest.json

jq -e '
  . as $m
  | .version == "0.5.1"
    and (.commit | test("^[0-9a-f]{40}$"))
    and (.release_url | endswith("/releases/tag/v0.5.1"))
    and (.workflow_run_url | test("/actions/runs/[0-9]+$"))
    and .policy_contract == "github-oidc-exchange.apelogic.io/v5"
    and .identity_contract == "steward-task-v2"
    and (.public_image_digest | test("^sha256:[0-9a-f]{64}$"))
    and (.public_chart_digest | test("^sha256:[0-9a-f]{64}$"))
    and (.ecr_image_digest | test("^sha256:[0-9a-f]{64}$"))
    and (.ecr_chart_digest | test("^sha256:[0-9a-f]{64}$"))
    and ($m.image | endswith("@" + $m.public_image_digest))
    and ($m.chart | endswith("@" + $m.public_chart_digest))
    and ($m.ecr_image | endswith("@" + $m.ecr_image_digest))
    and ($m.ecr_chart | endswith("@" + $m.ecr_chart_digest))
    and (.image_platforms.linux.amd64 | test("^sha256:[0-9a-f]{64}$"))
    and (.image_platforms.linux.arm64 | test("^sha256:[0-9a-f]{64}$"))
' release-manifest.json >/dev/null

for field in image chart; do
  reference="$(jq -r --arg field "$field" '.[$field]' release-manifest.json)"
  digest="${reference##*@}"
  oras manifest fetch --descriptor "$reference" | jq -e --arg digest "$digest" \
    '.digest == $digest' >/dev/null
  cosign verify --certificate-identity "$RELEASE_IDENTITY" \
    --certificate-oidc-issuer "$RELEASE_OIDC_ISSUER" \
    --experimental-oci11=true --new-bundle-format=true "$reference" >/dev/null
  cosign verify-attestation --certificate-identity "$RELEASE_IDENTITY" \
    --certificate-oidc-issuer "$RELEASE_OIDC_ISSUER" \
    --experimental-oci11=true --new-bundle-format=true \
    --type spdxjson "$reference" >/dev/null
  cosign verify-attestation --certificate-identity "$RELEASE_IDENTITY" \
    --certificate-oidc-issuer "$RELEASE_OIDC_ISSUER" \
    --experimental-oci11=true --new-bundle-format=true \
    --type slsaprovenance1 "$reference" >/dev/null
done
```

The public `image` and `chart` references are anonymously pullable. After
authenticating to the release ECR registry, repeat the signature and two
attestation checks for `ecr_image` and `ecr_chart`. The v0.5.0 rollback
coordinates are in that release's signed manifest.
